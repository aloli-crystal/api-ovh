= api-ovh
:toc: left
:toc-title: Table des matières
:toclevels: 3
:source-highlighter: rouge
:icons: font

Client Crystal pur (stdlib uniquement) pour l'API https://api.ovh.com/console/[OVHcloud v1].
Modules typés pour le périmètre opérateur du quotidien (clés SSH, serveurs
dédiés + install + rescue, DNS inverse, zones DNS, SMS) au-dessus d'un
transport signé générique (`raw_get`/`raw_post`/`raw_put`/`raw_delete`)
qui atteint *n'importe quel* endpoint v1.

[NOTE]
====
*api-ovh* s'intègre dans l'écosystème Aloli aux côtés de
https://github.com/aloli-crystal/beryl[beryl] (configuration FreeBSD agentless)
et https://github.com/aloli-crystal/silex[silex] (writer FAT12 cloud-init).
Zéro dépendance externe : uniquement `HTTP::Client`, `OpenSSL`, `JSON` de la stdlib Crystal.
====

== Pourquoi api-ovh ?

Les clients OVH officiels sont écrits en Python, Node, Go, PHP ou Java, mais pas en Crystal.
Les wrappers Crystal existants sont abandonnés ou dépendent de shards HTTP tiers.

api-ovh implémente la signature `X-Ovh-Signature` localement (SHA-1), s'appuie
exclusivement sur la stdlib et expose une API idiomatique Crystal, testable par
injection de transport.

== Caractéristiques

* *Pure Crystal* : aucune dépendance runtime (stdlib `HTTP::Client`, `OpenSSL`, `JSON`).
* *Signature OVH* : calcul local de `$1$ + SHA1(secret+ck+method+url+body+timestamp)`.
* *Offset d'horloge* : `/auth/time` interrogé une seule fois, offset mémorisé.
* *Routage multi-endpoint* : `:eu` (défaut), `:ca`, `:us`, Kimsufi, SoYouStart.
* *Modules typés* : `ssh_keys`, `dedicated_servers` (list / info /
  reinstall / tasks / boot+rescue / `wait_for_task`), `ips` (DNS
  inverse), `domains` (zones DNS), `sms`, `auth` (génération de
  consumer key, credential courant, expiration).
* *Échappatoire brute* : `client.raw_get`, `raw_post`, `raw_put`,
  `raw_delete` attaquent n'importe quel endpoint non couvert
  (`/me/api/credential`, `/me/identity`, `/secret`, `/ssl`, `/cloud`,
  `/services`…) avec la même signature et la même gestion d'erreurs.
* *Transport injectable* : `HttpTransport` abstrait, stub trivial pour les specs.
* *Taxonomie d'erreurs* : `AuthenticationError`, `NotFound`, `RateLimited`,
  `ApiError` (avec `errorCode` et `http_status`), `TaskTimeout`
  (porte la dernière `Task` observée).

== Périmètre

[cols="1,3"]
|===
| Couche | Couverture

| Modules typés
| Clés SSH (`/me/sshKey`), serveurs dédiés (`/dedicated/server` —
  list, info, reinstall, tasks, `wait_for_task`, boot, rescue, reboot,
  `boot_from_disk`, displayName), DNS inverse (`/ip/{ip}/reverse`),
  zones DNS (`/domain/zone/*/record`), SMS (`/sms` — services + envoi),
  helpers d'auth (`/auth/credential`, `/auth/time`, demande de
  consumer key).

| Accès brut (`raw_*`)
| Tout autre endpoint v1 atteignable via un appel signé qui retourne
  `JSON::Any?`. Exemples : `/me/api/credential` (rotation des
  consumer keys), `/me/identity/{user,group}` (IAM), `/me/accessRestriction`
  (MFA / IP allow-list), `/secret` (KMS), `/ssl` (certificats),
  `/services` (inventaire des actifs), `/cloud/*`, `/order/cart`,
  `/dbaas/logs`.

| Hors-périmètre
| OAuth 2.0 applicatif (le schéma API Keys + consumer key reste la
  voie officielle d'OVH sur la v1).
|===

== Installation

Dans votre `shard.yml` :

[source,yaml]
----
dependencies:
  api-ovh:
    github: aloli-crystal/api-ovh
    version: ~> 0.7
----

Puis `shards install`.

== Démarrage rapide

[source,crystal]
----
require "api-ovh"

client = OvhApi::Client.new(
  application_key:    ENV["OVH_APPLICATION_KEY"],
  application_secret: ENV["OVH_APPLICATION_SECRET"],
  consumer_key:       ENV["OVH_CONSUMER_KEY"],
  endpoint:           :eu,
)

# Clés SSH
client.ssh_keys.list                              # => ["laptop", "desktop"]
client.ssh_keys.create(name: "laptop", key: "ssh-ed25519 AAAA...")

# Serveurs dédiés
servers = client.dedicated_servers.list           # => ["ns1.ip-1-2-3.eu"]
info    = client.dedicated_servers.info(servers.first)

# Installation Debian 12
task = client.dedicated_servers.reinstall(
  service_name: "ns1.ip-1-2-3.eu",
  template:     "debian12_64",
  hostname:     "web01.aloli.fr",
  ssh_key_name: "laptop",
)

# Polling jusqu'à un état terminal (lève TaskTimeout si dépassement)
final = client.dedicated_servers.wait_for_task(
  service_name: "ns1.ip-1-2-3.eu",
  task_id:      task.id,
  interval:     30.seconds,
  timeout:      1.hour,
)
raise "install KO : #{final.comment}" if final.failed?

# DNS inverse
client.ips.set_reverse(ip: "192.0.2.10", reverse: "web01.aloli.fr.")
----

L'exemple complet est dans link:examples/provision_debian.cr[`examples/provision_debian.cr`].

== Orchestration rescue OVH

Depuis la v0.2.1, api-ovh expose les endpoints de netboot / reboot et un
helper de haut niveau `prepare_rescue` qui enchaîne trois étapes pour
basculer un serveur en mode rescue avec une clé SSH posée :

. Recherche du `bootId` `rescue` UEFI-compatible via
  `GET /dedicated/server/\*/boot` puis `GET .../boot/\{id\}`.
. `PUT /dedicated/server/\*` avec `{"bootId": <rescueId>, "rescueSshKey": "<ssh-key-name>"}`
  (un seul appel — `rescueSshKey` est un champ du serveur, pas une
  option séparée).
. `POST /dedicated/server/\*/reboot` → `Task`.

[source,crystal]
----
# La clé doit déjà exister dans /me/sshKey.
client.ssh_keys.list.includes?("laptop") # => true

task = client.dedicated_servers.prepare_rescue(
  service_name: "ns1.ip-1-2-3.eu",
  ssh_key_name: "laptop",
)
puts "Tâche rescue #{task.id} (#{task.status})"

client.dedicated_servers.wait_for_task(
  service_name: "ns1.ip-1-2-3.eu",
  task_id:      task.id,
  interval:     15.seconds,
)
----

Les appels bas niveau restent accessibles individuellement
(`boots`, `boot`, `set_boot` avec options `rescue_ssh_key` et
`rescue_mail`, `reboot`) si vous avez besoin d'un orchestrateur
différent (ex. basculer en `ipxeCustomerScript`).

== Accès brut à l'API (échappatoire)

Tout ce qui n'est pas dans les modules typés s'attaque via les quatre
helpers signés ci-dessous. Le caller navigue le `JSON::Any?` retourné
lui-même. Même signature, même taxonomie d'erreurs, même routage
multi-endpoint.

[source,crystal]
----
# A.5.17 (ISO 27001) — lister les consumer keys actives pour rotation
ids = client.raw_get("/me/api/credential",
  query: {"status" => "validated"}).not_nil!.as_a.map(&.as_i)

# A.5.17 — révoquer une consumer key compromise
client.raw_delete("/me/api/credential/#{ids.first}")

# A.8.16 — inventaire complet des actifs
services = client.raw_get("/services").not_nil!.as_a

# A.8.24 — lister les certificats SSL
certs = client.raw_get("/ssl").not_nil!.as_a

# POST avec corps JSON arbitraire
client.raw_post("/secret/v1/secrets",
  body: {"name" => "db-password", "value" => "s3cr3t"})
----

Préférer un module typé (`client.ssh_keys`, `client.dedicated_servers`,
…) quand il existe : meilleure ergonomie et stabilité du typage face
aux évolutions de schéma OVH. Réserver `raw_*` à la longue traîne.

== Obtenir des credentials OVH

. Créer une application sur https://eu.api.ovh.com/createApp/[eu.api.ovh.com/createApp] →
  récupère `application_key` et `application_secret`.
. Générer un consumer key avec les scopes nécessaires sur
  https://eu.api.ovh.com/createToken/[eu.api.ovh.com/createToken] :
+
[source]
----
GET  /me/sshKey
POST /me/sshKey
GET  /dedicated/server
GET  /dedicated/server/*
GET  /dedicated/installationTemplate
POST /dedicated/server/*/reinstall
GET  /dedicated/server/*/task
GET  /dedicated/server/*/task/*
GET  /ip/*/reverse
POST /ip/*/reverse
GET  /dedicated/server/*/boot
GET  /dedicated/server/*/boot/*
PUT  /dedicated/server/*
POST /dedicated/server/*/reboot
----
. Valider l'URL retournée (SMS ou mot de passe manager OVH) : le consumer key
  est alors actif.

[TIP]
====
L'étape 2 est automatisable de bout en bout via
`client.auth.request_consumer_key`, qui soumet les access rules et
retourne l'URL de validation avec le nouveau consumer key. Voir le
module `Endpoints::Auth`.
====

== Tester contre la vraie API

Les specs tournent avec un `FakeTransport` stdlib-pur, sans appel réseau. Pour
un test d'intégration contre la vraie API OVH :

[source,sh]
----
export OVH_APPLICATION_KEY=...
export OVH_APPLICATION_SECRET=...
export OVH_CONSUMER_KEY=...
crystal run examples/provision_debian.cr
----

Sans `OVH_CONFIRM=yes`, l'exemple s'arrête *avant* de lancer la réinstallation :
il se contente de lister les clés, serveurs et templates.
