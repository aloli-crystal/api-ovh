=== Note d'activation

La publication des docs sur GitHub Pages requiert *une opération

*Settings → Pages → Build and deployment → Source : GitHub Actions*.
Sans ça, le job `deploy-docs` échouera avec un message explicite.

== 0.7.0 (3 mai 2026)

=== Ajouté

* `client.dedicated_servers.wait_for_task(service_name, task_id,
  interval:, timeout:)` : helper synchrone qui polle la tâche jusqu'à
  un état terminal (`done?`) et retourne la `Task` finale. Remplace
  les `loop do … sleep` à recopier côté appelants.
+
[source,crystal]
----
final = client.dedicated_servers.wait_for_task(
  service_name: "ns1.ip-1-2-3.eu",
  task_id:      task.id,
  interval:     30.seconds,
  timeout:      1.hour,
) { |t| Log.info { "Task #{t.id} : #{t.status}" } }
raise "install KO : #{final.comment}" if final.failed?
----
+
Le bloc `do |task| … end` est optionnel et permet de tracer chaque
poll (logs structurés, télémétrie). Lève `OvhApi::TaskTimeout` si la
tâche reste non-terminale au-delà du `timeout` ; l'exception porte
`#last_task` pour permettre à l'appelant de re-poller ou d'agir.
* `OvhApi::TaskTimeout < OvhApi::Error` : nouvelle exception, expose
  la dernière `Task` observée via `#last_task`.
* `FakeTransport#stub_sequence` côté specs : permet de tester
  facilement les scénarios à plusieurs polls (chaque appel renvoie la
  réponse suivante de la séquence, le dernier élément reste collant).

== 0.6.0 (3 mai 2026)

=== Ajouté

* `client.raw_get`, `client.raw_post`, `client.raw_put`, `client.raw_delete` :
  échappatoires génériques pour appeler n'importe quel endpoint OVH non
  couvert par un module typé. Utiles en attendant la couverture des
  sections IAM (`/me/api/credential`, `/me/identity`, `/me/accessRestriction`),
  cryptographie (`/secret`, `/ssl`), inventaire (`/services`) ou audit
  (`/me/api/logs/calls`).
+
[source,crystal]
----
# Lister les consumer keys validées (A.5.17 — rotation des credentials)
ids = client.raw_get("/me/api/credential",
  query: {"status" => "validated"}).not_nil!.as_a.map(&.as_i)

# Révoquer une CK compromise
client.raw_delete("/me/api/credential/#{ids.first}")
----
+
Le caller récupère un `JSON::Any?` qu'il navigue lui-même : pas de
typage, mais accès immédiat à tout endpoint v1 OVH. Préférer un module
typé (`client.ssh_keys`, `client.dedicated_servers`…) quand il existe.
* Specs couvrant les 4 méthodes : signature, sérialisation JSON
  compacte du corps, encodage de la query, propagation des erreurs.

== 0.5.0 (2 mai 2026)

=== Ajouté

* `client.sms` — nouvel endpoint pour piloter un service SMS OVH
  pré-payé. Trois méthodes :
  ** `services` — liste des `serviceName` accessibles à la consumer key
     courante (utile pour valider la config au boot).
  ** `service(name)` — métadonnées d'un service (`credits_left`, status,
     `callback_url`). Sert à anticiper la rupture de crédit.
  ** `send(service_name, receivers, message, sender:, no_stop_clause:,
     priority:, validity_period:)` — envoi synchrone d'un SMS à une
     liste de numéros E.164. Renvoie un `JobResult` qui distingue les
     `valid_receivers` des `invalid_receivers` (numéro mal formé ou
     blacklisté).
* Records publics : `Endpoints::ServiceInfo` et `Endpoints::JobResult`.
* Pré-requis OVH : un pack SMS commandé (https://www.ovhtelecom.fr/sms/),
  une consumer key avec scopes `GET /sms/*` + `POST /sms/*/jobs`
  (URL pratique : https://eu.api.ovh.com/createToken/?GET=/sms/*&POST=/sms/*/jobs),
  et un sender 3-11 alphanumériques validé par OVH.

== 0.2.3 (20 avril 2026)

== 0.2.2 (20 avril 2026)

=== Corrigé

* `prepare_rescue` : le champ OVH `rescueSshKey` attend la **clé publique
  brute** (`ssh-ed25519 AAAA... user@host`), pas le nom de la clé. La
  doc OVH indique pourtant « name of the ssh key », ce qui est trompeur
  — l'API renvoie `400 {"message":"SSH key is not valid"}` quand on
  passe le nom. Vérifié en consultant `GET /dedicated/server/{serviceName}` :
  le champ `rescueSshKey` du serveur y est stocké en contenu brut.
+
`prepare_rescue` fait désormais un `GET /me/sshKey/{name}` pour
récupérer le contenu avant de le passer à `set_boot`. L'API
publique est inchangée (on passe toujours le nom en argument) :
compatibilité ascendante côté appelants.

=== Ajouté

* Spec étoffé : couvre le lookup intermédiaire `ssh_keys.get` + assertion
  que le `PUT` envoie la clé brute, pas le nom.

==== Fondations du projet

* Squelette initial (`shard.yml`, `LICENSE` MIT, README bilingue FR/EN).
* Convention Aloli : branche par défaut `production`, messages de commit
  en français, licence MIT, auteurs `ALOLI sas`.

==== Cœur du client

* `OvhApi::Client` : signature `X-Ovh-Signature` locale (SHA-1 hex préfixé
  par `$1$`), calculée sur `secret+ck+method+url+body+timestamp`.
* Synchronisation d'horloge via `/auth/time` (mémorisation d'un offset,
  évite de re-interroger à chaque appel).
* Routage multi-endpoint : `:eu` (défaut), `:ca`, `:us`, Kimsufi EU/CA,
  SoYouStart EU/CA. L'argument accepte aussi une URL complète.
* Transport HTTP abstrait `OvhApi::HttpTransport` avec implémentation
  `DefaultHttpTransport` (stdlib `HTTP::Client`), permet l'injection d'un
  double en test.

==== Endpoints de provisioning

* *SSH keys* (`/me/sshKey`) : `list`, `get`, `create(name, key, default)`,
  `delete`.
* *Dedicated servers* (`/dedicated/server`) : `list`, `info`, `reinstall`
  (endpoint moderne 2024 avec `operatingSystem` + `customizations`),
  `installation_templates`, `tasks` (avec filtres `function`/`status`),
  `task` (détail individuel).
* *Reverse DNS* (`/ip/{ip}/reverse`) : `list`, `get_reverse`, `set_reverse`,
  `delete_reverse`.

==== Taxonomie d'erreurs

* `OvhApi::Error` (base).
* `AuthenticationError` (HTTP 401/403).
* `NotFound` (HTTP 404).
* `RateLimited` (HTTP 429, expose `retry_after`).
* `ApiError` (autres, expose `http_status` et `error_code`).

==== Tests et exemples

* Specs Crystal avec `FakeTransport` pur stdlib (aucun appel réseau) :
  signature, offset d'horloge, en-têtes, corps JSON, query string,
  gestion d'erreurs, sérialisation des `Task` et `Reverse`.
* Vecteur de signature déterministe recalculé à la main dans les specs.
* Exemple exécutable `examples/provision_debian.cr` : installation Debian 12
  + polling de tâche + pose de reverse DNS, avec garde-fou `OVH_CONFIRM=yes`.

==== Intégration continue

* CI GitHub Actions : format Crystal + specs sur Linux et FreeBSD 15
  via `cross-platform-actions/action`, avec compilation de l'exemple
  (`mkdir -p bin && crystal build ...`).
